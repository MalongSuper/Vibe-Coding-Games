# Vibe Coding Games

A collection of games created through **Vibe Coding** — using multiple AI models to design, generate, debug, and refine playable games from natural-language prompts.

The goal of this repository is to explore how far we can take game development by combining the strengths of different AI models rather than relying on a single AI to handle the entire process.

## What Is the Result?

The final result of each project is designed to be **simple, portable, and immediately playable**:

* A **single HTML file**
* CSS for styling and visual presentation
* JavaScript for game logic and interactions
* HTML5 **Canvas** when required for rendering
* No complicated build system or framework required
* Can generally be opened directly in a web browser

In other words, the objective is to go from an idea or prompt to a **self-contained playable game** that can be shared as a single `.html` file.

## What Kind of Games?

Most games in this repository are inspired by or built around **famous and recognizable game genres and mechanics**.

Examples include:

* **Puzzle Games** — games focused on logic, matching, solving, and strategic thinking
* **Endless Games** — games where the player continuously survives, runs, avoids obstacles, or tries to achieve a high score
* **Multiplayer Games** — local player-vs-player experiences where multiple players interact with the same game
* **CPU / AI Games** — games featuring computer-controlled opponents whose behavior is determined entirely by predefined game logic
* **Action Games** — combat, enemies, abilities, and real-time interactions
* **Arcade Games** — simple mechanics designed around scoring, timing, reaction, and replayability
* **Strategy Games** — games where players make decisions based on game state, resources, positioning, or rules

The intention is not necessarily to reproduce existing games exactly. Instead, familiar genres and mechanics provide a foundation for experimenting with **AI-generated game design and implementation**.

## Multi-AI Vibe Coding Workflow

Rather than asking one AI to do everything, this repository uses multiple AI models with **different roles in the development process**.

### 1. DeepSeek — Prompt Improvement & Minor Fixes

**Role:** Prompt engineer + minor debugger

DeepSeek is primarily used to:

* Improve and clarify the initial user prompt
* Turn rough game ideas into more structured requirements
* Identify missing details or ambiguities
* Suggest gameplay rules and implementation requirements
* Fix minor bugs after the initial generation
* Make small adjustments and refinements to the generated game

DeepSeek acts as a bridge between the original idea and the implementation, helping turn a vague concept into a prompt that another AI can execute more effectively.

### 2. Claude — Complete Code Generation

**Role:** Main game developer

Claude is primarily responsible for generating the game **from scratch**.

Given the improved prompt, Claude generates the complete implementation, including:

* HTML structure
* CSS styling
* JavaScript game logic
* Canvas rendering when necessary
* Player controls
* Game mechanics
* Scoring systems
* Enemies and/or CPU behavior
* User interface
* Animations and visual effects
* Game states such as menus, gameplay, victory, and game over

The goal is for Claude to produce a complete, playable game in a **single HTML file**.

### 3. Gemini — Major Bug Fixing & Refinement

**Role:** Code reviewer + major debugger

Gemini receives the code generated by Claude and is primarily used to identify and fix **larger problems**.

This can include:

* Major gameplay bugs
* Broken game mechanics
* Incorrect state management
* Rendering problems
* JavaScript errors
* CPU behavior problems
* Input and interaction issues
* Problems caused by the interaction of multiple game systems
* Other issues that prevent the game from functioning as intended

Gemini therefore acts as the second development pass, taking the generated game and making it more stable and playable.

## 🔄 The Workflow

The general Vibe Coding pipeline looks like this:

**Game Idea**

↓

**DeepSeek**
Improve and structure the prompt

↓

**Claude**
Generate the complete game from scratch

↓

**Gemini**
Review the generated code and fix major bugs

↓

**DeepSeek**
Fix minor issues and make additional refinements

↓

**Playable HTML Game**

This workflow allows different models to contribute at the stage where they are most useful.

## 💡 Why Multiple AIs?

Different AI models can have different strengths when working with code.

Instead of expecting one model to simultaneously:

> understand the idea → design the game → write thousands of lines of code → debug everything → polish the result

the workflow separates these responsibilities into multiple stages.

This makes the development process closer to a **software development pipeline**, where one stage produces an artifact that the next stage reviews, improves, or repairs.

The repository therefore serves not only as a collection of games, but also as an experiment in:

* AI-assisted programming
* Prompt engineering
* Multi-model development
* AI code generation
* AI debugging
* Rapid game prototyping
* Vibe Coding workflows

## 📁 Repository Philosophy

The games in this repository are intentionally lightweight.

The primary objective is not to build production-scale commercial games, but to explore what can be accomplished when **natural-language ideas are converted into functioning games through AI-assisted development**.

Each game represents an experiment:

**How much game can we create by simply describing what we want and letting multiple AIs build it?**

The answer is contained in the playable HTML files throughout this repository.
